## Escaped bugs

**1 escaped, 0 caught before main**

- **What it counts:** Bugs that got past every check that ran on their change and were found later, from the root-cause pages in docs/rca and from issues filled in with the escaped-bug form.
- **Why it is tracked:** Each one is a place the checks have a gap. The list says which layer should have caught it and what test now does.
- **How it can mislead:** A low count can mean few bugs or few people looking. Fixing a bug without logging it makes the number look better. The count of escaped bugs alone says nothing about severity.

## Flaky rate

**2.6% of CI runs on main passed only after a re-run**

- **What it counts:** Finished CI runs on main (pushes, the nightly run and manual runs) whose first attempt failed and a later attempt passed, divided by finished runs. A run that failed and stayed red is not flaky, and neither is a green run someone ran again.
- **Why it is tracked:** A suite that passes on a re-run teaches people to re-run instead of read. The rate shows how often that happens.
- **How it can mislead:** A re-run after a real outage (a package registry down, for example) counts too. And a flaky test that people have stopped re-running, because they skip it, does not count at all.

## Time to fix a red main

**median 3.3 h over 1 red**

- **What it counts:** From the first failed run on main to the start of the next green one. Several failed runs in a row are one red.
- **Why it is tracked:** A red main blocks everyone and hides new failures. How quickly it goes green again shows whether people treat a failing check as urgent.
- **How it can mislead:** A fix that only turns the check off is fast and wrong. Weekend and overnight reds count their full length, so they pull the median up.

## CI run time

**median 3.1 min, slowest tenth 4.3 min**

- **What it counts:** Minutes from the start to the end of the last attempt of each finished CI run on main.
- **Why it is tracked:** A pipeline people wait on is a pipeline people skip. The slowest tenth shows what a bad day feels like, not just the average one.
- **How it can mislead:** A faster run can mean fewer or weaker checks. Read it next to the escaped bugs.

## Left Out On Purpose

The number of tests and code coverage are not here. More tests do not mean fewer escaped bugs, and a target for either one rewards writing tests that are easy to pass.
